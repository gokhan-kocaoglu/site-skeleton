## Evidence-only delta modeli

`v1.0.0`, denetlenen RC2 ağacına **uygulama değişikliği eklemez**. Aradaki tek
fark kanıt dokümantasyonudur. Zincir:

```text
v1.0.0-rc.2 audited tree
→ final audit evidence PR
→ final evidence merge + post-merge main CI
→ terminal memory-only closure PR
→ closure merge + post-merge main CI
→ immutable v1.0.0 release
```

**Bağlayıcı kural:**

```text
V1_RELEASE_TARGET_SHA = V1_FINAL_EVIDENCE_CLOSURE_MERGE_SHA
```

**Neden closure merge SHA'sı:** daha erken bir SHA tag'lenirse release, kendi
kanıt paketini (bu taslak + RC2 audit raporu) veya paketin kapanış kaydını
kapsamaz. Bu kural `docs/operations/release-attestation.md`'deki beş aşamalı
zamansal modelin aynısıdır.

## Kabul edilmiş açık riskler

Hiçbiri release-blocking değildir; tamamı kayıtlı ve sahiplidir.

### 1. Tarihsel kabul edilmiş riskler

| Risk | Severity | Sahip |
|---|---|---|
| Optional module hardening (BFF-1/2/3) | MEDIUM | Aktivasyon-anı implementer |
| Hook tam shell parser değildir | LOW | Orkestratör |
| Type-aware lint derinliği (ADR-0012) | LOW | Orkestratör |

### 2. R-4 açık borcu

```text
Node sürüm/EOL otomatik gate'i yok
Severity: MEDIUM
Non-blocking
```

`gate-toolchain` **yalnız** `packageManager`/pnpm politikasını denetler; Node
sürümünü veya Node EOL durumunu **kontrol etmez**. Node 22 hattı denetim anında
Maintenance LTS'tir (EOL 2027-04-30), dolayısıyla borç bugün somut bir açığa
dönüşmemektedir.

### 3. RC1'den açık kalan non-blocking bulgular

`F4-MEDIUM-01` (aktivasyon kapısı kapsamı) · `F4-MEDIUM-02` (README/CLAUDE RC
durumu) · `F4-MEDIUM-03` (core web güvenlik başlığı politikası) ·
`F4-LOW-01…-06`.

**`F4-LOW-03` düzeltilmiş çerçeve:** RC1'in "ruleset ↔ anayasa çelişkisi"
tanımı hatalıydı — repository anayasası squash/rebase'i **yazılı olarak
yasaklamıyor**. Gerçek sorun sıralaması: **önce** yazılı merge yöntemi
politikası, **sonra** ruleset enforcement (`allowed_merge_methods`).

### 4. RC2'de yeni bulunan non-blocking bulgular

`F4R2-MEDIUM-01` (operasyon/release dokümantasyonu release gerçekliğiyle
senkron değil) · `F4R2-LOW-01` (guard yalnız beyanı doğruluyor, çalışan pnpm
ikilisini değil) · `F4R2-LOW-02` (`skeleton-brief.md` iç tutarsızlığı) ·
`F4R2-LOW-03` (brief major yükseltme maliyetini küçük gösteriyor).

**RC2'de yeni bulunan bulgu sayısı:**

```text
CRITICAL 0
HIGH 0
MEDIUM 1
LOW 3
```

Bu sayılar **yalnız RC2'de yeni bulunanlardır**; yukarıdaki 1–3 numaralı
gruplardaki açık risklerin toplamı değildir.
