## 4. P0-4 — Merge-sonrası memory closure

### Eski akış (kaldırıldı)

```text
implementation → memory → commit/push → final rapor
```

Main korumalı olduğu için bu sıra çalışmıyordu: kapanış dosyası merge'den ÖNCE
yazılıyor ve merge anında bayatlıyordu (HIGH-4'ün kök nedeni).

### Yeni bağlayıcı akış

```text
implementation dalı biter → PR → required check'ler yeşil → MERGE
→ lokal main güncellenir
→ merge SHA + PR no + post-merge main CI run kaydedilir
→ güncel main'den chore/memory-close-<yyyy-mm-dd>-<project-slug> dalı
→ memory-steward: Current Status + session log → closure commit
→ closure hash Current Status'e → seal commit
→ memory-only closure PR → required check'ler → merge → süreç biter
```

### Memory-only closure PR — terminal istisna

Closure PR **kendisi için yeni closure üretmez**. Yalnız `project-memory/**`
(+ açıkça izin verilmiş closure kanıtı) taşır ve governance zincirinin son
halkasıdır. Bu istisna açıkça belgelenmeseydi her memory PR yeni bir memory PR
gerektirir, sonsuz döngü oluşurdu.

Hizalanan canonical yüzeyler: `skills/memory-protocol` · `skills/feature-workflow` ·
`commands/finish-session` · `rules/common/development-workflow` ·
`rules/common/git-workflow` (+ `rules/common/hooks` tablo satırı).
`/finish-session` sekiz ön koşulu tek tek doğruluyor ve
`Son Uygulama Commiti` artık **feature merge commit'i** + PR no + post-merge
main CI run ID/URL taşıyor.

## 14. P1.8 — Formal Task Card zorunluluğu

Enforcement artık **formal işarete** bağlı (`TASK CARD`, case-insensitive).
Eski davranış tersine dönmüştü: tek bir risk alanından söz eden mikro todo
bloklanıyor, hiçbir alan taşımayan formal PM kartı serbest geçiyordu.

- Formal + dört alan tam → sessiz kabul (exit 0)
- Formal + eksik/boş/gerekçesiz `N/A` → stderr + **exit 2**
- İşaretsiz → hiçbir koşulda bloklanmaz (kısmi alan formal yapmaz)
- İşaretsiz + dört alan tam → sessiz kabul

`/start-feature` ve `feature-workflow`: PM'nin ürettiği **bütün** kartlar
formaldir ve `00_System/Task-Card-template.md` formatını kullanır.

| Formal + bir alan eksik | exit 2 | exit 2 | exit 2 |

## Post-CI Memory-Only Rename Remediation (2026-07-28)

### Bağlam

| Öğe | Değer |

CI'nın yeşil olması bu açığı göstermezdi: closure guard yalnız gerçek bir
memory-only closure koşusunda devreye girer ve o senaryo henüz hiç
çalıştırılmamıştı. Açığı bulan şey testler değil, diff incelemesidir.

### Bulgu 1 — rename'in yalnız hedef tarafı denetleniyordu

Eski ayrıştırma:

```js
.map((line) => line.slice(3).replace(/^"|"$/g, '').split(' -> ').pop().trim());
```

`git status --porcelain=v1` rename kaydını insan-okur biçimde
`R  <orig> -> <new>` verir. `.split(' -> ').pop()` yalnız **hedefi** alır, yani:

```text
R  docs/operations/example.md -> project-memory/.../example.md
```

kaydı sadece `project-memory/.../example.md` olarak değerlendirilip **izinli**
sayılıyordu. Oysa bu kayıt aynı zamanda `docs/operations/example.md`
dosyasının **silinmesidir**. Sonuç: memory-only closure branch'i, dosyayı
vault'un içine taşımak koşuluyla memory dışı herhangi bir dosyayı sessizce
silebilirdi — guard'ın engellemek için var olduğu şeyin tam kendisi.

Ayrıca alıntılı yollar (`"docs/outside evidence.md"`) bu metin-tabanlı bölmede
bozuluyordu.

### Bulgu 2 — session flag prefix eşleşmesi

```js
ALLOWED_DIRTY.some((ok) => rel.startsWith(ok))
```

`.claude/hooks/.session-close-pending` bir **tam yol** izniyken prefix olarak
kullanılıyordu. Bu yüzden `.session-close-pending-extra`,
`.session-close-pending.backup` gibi sıradan dosyalar da izinli sayılıyor ve
memory-only PR'a kaçak girebiliyordu.

### Düzeltme

Ayrıştırma `-z` (NUL-delimited) biçimine geçirildi. Kayıt şekli **varsayılmadı,
git 2.51 üzerinde ampirik olarak doğrulandı**:

```text
ordinary     "XY <path>\0"
rename/copy  "XY <NEW-path>\0<ORIG-path>\0"
```

Sıraya dikkat: `-z` ile **hedef önce**, orijinal kendi NUL-sonlu alanı olarak
sonra gelir — insan-okur `orig -> new` biçiminin tersi. `-z` ayrıca yol
alıntılamasını kapatır, böylece boşluk/tırnak içeren yollar bozulmadan gelir.

- Rename/copy kayıtlarının **her iki tarafı** ayrı dirty path olarak denetlenir.
- Çözümlenemeyen veya kaynak yolu eksik kayıt **açık problem** üretir
  (fail-closed): ayrıştırılamayan bir status, temiz ağaç kanıtı değildir.
- İzin kuralı tek ve açık bir fonksiyona indirildi:

```js
function isAllowedClosurePath(rel) {
  return rel.startsWith('project-memory/') ||
         ['.claude/hooks/.session-close-pending'].includes(rel);
}
```

Yollar `/` biçimine normalize edilir; offender listesi tekilleştirilir.
