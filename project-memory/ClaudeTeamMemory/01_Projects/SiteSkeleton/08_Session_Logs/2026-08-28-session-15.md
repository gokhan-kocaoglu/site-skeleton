## Tasarım Kararı

Stage 1 root-cause: Yalnız hyphen (`-`) marker topluyordu. Canonical metadata rows 
(release-state, historical-note, pairVector alan listeleri) korunurken asterisk (`*`), 
plus (`+`), ordered markers (1–9 + `.` veya `)`), bare marker kenarları (marker + satır 
sonu), quoted release-state hattı ve nested list-like metadata satırları eklendiğinde 
**görünmez false-PASS** üretebiliyordu. Bare marker'lar canonical metadata değildir 
— yalnızca non-canonical satırları ifade ederler.

**Tespit yöntemi**: salt-okuma git-aware RED reproduction (detached worktree; `git archive`
snapshot'ı authoritative baseline DEĞILDIR, git metadata olmadığından 1338 raporluyor).
Authoritative baseline **1340** (AC-26 closure merge sonrası). 

**Disposable RED/GREEN probe'ları** — git-aware detached worktree'de ölçülen false-PASS sınıfları:

```text
release-state    : `*` · `+` · `1.` · `1)`                    (4)
historical-note  : `> *` · `> +` · `> 1.` · `> 1)`            (4)
bare marker      : `*` · `2.` · `> *` · `> 2.`                (4)
nested blockquote: `> > *` · compact `>>*`                    (2)
quoted release-state: `> *`                                   (1)
                                                     toplam = 15
```

Bu ölçülen probe sınıfları tek seferlik reproduction kanıtıdır. On beş probe sınıfının **on dördü** 
kalıcı regression suite'e alındı; kalıcı suite'e girmeyen tek probe sınıfı compact `>>*`'dır. Buna ek olarak 
whitespace-indented `    -` regression guard kalıcı suite'e eklendi (bu bir false-PASS sınıfı değil, önceki 
kapsamın daralmadığını kanıtlayan kontroldür). Toplam kalıcı senaryo: 15. Tab-indented ve historical-indent 
kontrolleri yalnız probe olarak kaldı.

**Remediation aşaması**:
1. Governance list-like detector marker ailesini `-` `+` `*` ve 1–9 basamak + `.`/`)` olmak üzere genişlet.
2. Bare marker tanımı: marker + satır sonu (`-$`, `+$`, `*$`, ve ordered bare marker'lar `2.`, `2)` gibi) sayılır.
3. Quoted release-state: sıfır veya daha fazla quote prefix; marker ve trailing whitespace korunur.
4. Nested list-like: blockquote derinliği (`> > *`, compact `>>*`) görülür.
5. Permissive whitespace coverage (`\s*` girinti, blockquote compact modları) **korundu** — Dar whitespace
   tasarımı (0–3 boşluk gibi) mevcut kapsamı **daraltacaktı**; 4-boşluk ve tab girintili hyphen
   bugün toplanıyor, geriye uyumluluğu korur.
6. Stage 2 (`STATE_BULLET_RE`, `RC1_NOTE_ROW_RE`, alan listeleri, pairVector, count/duplicate/forbidden)
   **değiştirilmedi**; yeni marker'lar canonical olmadı, Stage 1 görür Stage 2 stray olarak reddeder.
7. Yeni reason code yok; mevcut AC-32 hyphen senaryoları **sıfır beklenti düzenlemesiyle** geçti.
